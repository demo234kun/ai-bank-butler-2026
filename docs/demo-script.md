# 演示脚本（5 分钟视频 / 现场答辩）

> 目标：5 分钟内同时给到「体验」与「安全」，并让评委当场看到底层链路。
> 默认演示时间 2026-10-30 10:00；配偶林晚生日 11-02，因此“生日前 2 天”正好可演示。

## 0. 演示前检查（30 秒）

1. 打开产品端（公网 HTTPS 链接或 http://localhost:5173），点「一键体验」创建独立访客账户。
2. 首页确认账户数据、AI 提醒、最近交易正常；看首页数据源标识：默认「合成数据」/「演示环境」。若使用 HTTP 接入，会显示合作银行名称与「银行核心直连」。若之前演示过，进入「我的 → 数据源 / 重置」检查。
3. 若网络不稳定，进入「我的 → 离线兜底」；规则引擎可完整跑完 6 个场景。
4. 评委控制台：登录后从「我的 → 评委控制台」打开 `/console`，确认「实时链路、审计链完整」。
5. 手机演示时直接用浏览器全屏；如果需要安装，点「我的 → 添加到主屏幕」。
6. 演示前不要把公开链接发给大量无关人员，避免多人同时创建访客消耗 LLM 配额。

## 2. 关键话术（答辩时可直接用）

- **权限为什么不写在提示词里？** 提示词可以被注入，权限不能。我们的工具白名单、风险引擎、一次性授权、额度台账都在服务端执行层，模型被说服也不会多转一分钱。
- **如何防幻觉？** 所有数字来自工具结果；模型不生成事实。渲染后再做数字一致性守卫，证据里没有的金额/百分比会被拦截并回退模板。
- **为什么确认要断流？** SSE 不挂起等待人工；`run.paused` 后关闭连接，确认后用 seq 续传。刷新页面也能从快照恢复确认单。
- **1000 元是什么？** 黄色与红色的分界线。大额经强验证仍可执行，并继续占用当日累计。
- **回退会不会假装成功？** 只补偿可逆节点；不可逆操作转人工工单，UI 显示“部分完成 · 转人工”。
- **批量确认安全吗？** 确认单覆盖 3 个操作，但每个节点仍有独立 grant、独立 digest、执行前逐个校验。
- **LLM 挂了怎么办？** 缓存 + 规则引擎 + 离线开关；断网也能演示 6 个场景。
- **这是模拟吗？** 默认演示使用合成数据和 demo 核验；但工具层已经抽成 `BankingGateway`，配置 `BANKING_MODE=http` 后账户快照与全部资金操作都走签名银行核心，失败显式报错、不回退仿真；短信与人脸也有 `http` Provider。可以用 `npm run smoke:full` 现场证明这条路径跑通。
- **成本？** 每条用户消息最多 1 次 JSON 解析调用（失败重试 1 次），控制台显示 tokens、缓存命中、延迟与估算成本。

## 3. 10 分钟答辩提纲

1. **问题与洞察（1 分钟）**：路径长、入口深；Agent 能办事，但银行场景的第一性问题是“可授权、可审计、可回退”。
2. **方案总览（1.5 分钟）**：手机 PWA + 多用户登录 + /console 评委模式；6 场景、LLM + 规则、服务端 DAG 与安全内核。展示架构图。
3. **权限、账号与数据隔离（2 分钟）**：五档矩阵 T0–T4、静态档 + 风控智能体取高、digest/grant、收款人复述、人工审核、强验证、批量确认、额度台账；scrypt、签名 Cookie、会话归属校验与按用户审计。
4. **安全机制（2 分钟）**：事实锁定、数字守卫、注入三层、审计链、熔断、沙箱、时间/TTL 设计。
5. **现场演示（2.5 分钟）**：黄色 → 红色 → 账单 → 生日 → 注入 → 审计（压缩版）。
6. **验证与边界（1 分钟）**：123 单测、`smoke` / `smoke:bank` / `smoke:full`、真实 LLM e2e、公网 HTTPS/PWA 实测；说明默认 demo 与真实接入的切换方式，以及客户绑定、mTLS、对账等生产化剩余项。

## 4. 演示失败兜底

| 现象 | 处理 |
| --- | --- |
| 网络/LLM 超时 | 点顶部「离线兜底」；规则引擎覆盖 6 场景；控制台会显示 offline 来源 |
| 会话状态混乱 | 进入「我的 → 重置演示数据 / 重置本地会话与额度」；仅重置当前账号并创建新会话；HTTP 模式会重新拉银行快照 |
| 登录失效 / Cookie 问题 | 重新「一键体验」或注册；公网必须 HTTPS + `COOKIE_SECURE=1` |
| 公网隧道不可用 | 改用 localhost:5173 演示；或重新启动 cloudflared 获取新链接 |
| 确认单过期 | 90 秒 TTL；点「取消」后重新发起，或直接重置 |
| 演示时误触注入导致锁定 | 控制台「异常熔断」面板点「人工复核解锁」 |
| 浏览器窗口太窄 | 产品端按手机 430px 设计；评委控制台建议 ≥1280px 宽 / 1600×1000 |
| 端口占用 | `netstat -ano | findstr :8787`（Windows）或 `lsof -i :8787`，结束占用进程 |

## 5. 现场演示节奏建议

- 先用手机全屏走一遍「一键体验 → 首页 → AI 管家」，让评委先看到完整产品，再进控制台看链路。
- 再用 `/console` 解释 DAG、策略和审计；控制台只作为技术解释层。
- 不要一上来讲架构；先用 520 元转账让评委看到“说话即办”和“确认单”。
- 红色强验证是全场的信任高点，放慢速度，展示摘要、渠道、剩余额度。
- 账单是体验高点，指出异常和沙箱；不要在账单里停留太久。
- 生日联动展示“一次对话完成多任务 + 批量确认”，体现 DAG 的价值。
- 最后用注入和审计收尾，把“安全”从口号变成可操作的控制台。
