# 功能实现核查报告

> 面向答辩的功能说明与赛题对照表见 [feature-description.md](feature-description.md)。
> 核查日期：2026-10-31 · 代码版本：当前工作区
> 目标：逐项确认“比赛要求的功能是否真的实现”，并区分“已实现且可验证”“默认演示、可切换真实接入”“仍未实现”。

## 1. 结论

六大赛场要求场景均已实现可运行的端到端链路；权限、审计、注入、熔断、回滚、接管、沙箱等安全要求均有代码与自动化用例。产品化侧的多用户、PWA、评委控制台也已完成。

“真实机构接入”不是一个开关就能完成的：仓库已经把工具层与银行核心解耦成 `BankingGateway`，提供签名 HTTP 适配器、快照校验、短信 / 人脸 Provider 和契约联调桩；`npm run smoke:full` 能证明六场景与强验证全部经 HTTP 适配层跑通。但仓库不含真实银行凭据，客户绑定、行方准入、mTLS、异步对账仍需联调。默认仍是合成数据演示，界面上有明确标注。

## 5. 仍然“不是真实”的部分

这些是客观边界，不应在答辩中宣称已完成：

1. **默认数据仍是合成数据**：只有把 `BANKING_MODE=http` 并配好上游后才读真实账户。公网默认演示实例仍展示合成数据并明确标注。
2. **默认核验通道仍是演示**：短信在 demo 模式下改为**一次性随机码**并回传页面自动填入（真实通道不返回验证码）；人脸在浏览器不支持或未录入通行密钥时仍是页面演示动画，界面已明确标注"未采集真实人脸"。
3. **礼物商户与价格是固定产品目录**：花间集 / 云朵烘焙等是演示文案；真实场景需接生活服务商户与库存/配送。
4. **语音输入是演示按钮**：当前没有接 ASR，只是一段模拟动画。
5. **账号安全仍是原型级**：注册短信验证、找回密码、登录 MFA、服务端会话与设备撤销已实现，但缺 KYC/证件核验、设备指纹、授权同意管理，会话仍存放在单机 JSON，不能多实例共享；短信演示模式下验证码由服务端回传，接真实通道后不会回传。
6. **公网隧道是临时的**：Quick Tunnel 随进程变化；正式提交应使用持久托管。
7. **单机 JSON + 内存会话**：不适配多实例；生产需 Postgres/Redis。
8. **银行接入尚未行方联调**：客户绑定 `bref -> custId`、mTLS、OAuth/授权同意、异步对账、历史流水分页、WORM 审计外送未实现。
9. **审计链是本机文件**：防篡改可被发现，但不能阻止整文件删除；生产需 WORM / SIEM / 外部锚定。
10. **风险测评是简化问卷**：5 题 100 分、年度有效期、等级→R1…R5 上限的规则已落地，但题目与阈值需按行内适当性办法与产品说明书校准，且未接双录/电子签约等合规留痕。
11. **争议工单只到受理**：仿真核心返回 `reviewing` 且明确“演示环境不会自动退款”，退款/拒付结论、举证材料上传、进度通知需接行方差错系统。
12. **核心操作成功、回包失败窗口**：契约建议银行返回完整快照并实现幂等查询；真实网关需按接入文档补对账。
