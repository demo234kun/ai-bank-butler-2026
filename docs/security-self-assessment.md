# 安全自评报告

> 版本：v1.0 · 更新日期：2026-11-02 · 作品：AI 银行管家
> 性质：开发期自查，供比赛评审参考，不构成合规、法律或审计结论。
> 默认运行在合成数据与演示核验通道上。配置 `BANKING_MODE=http` / `SMS_MODE=http` / `FACE_MODE=http` 后，账户读写与核验改走签约服务，失败即关闭，不回退仿真数据。

## 0. 结论

原型已实现五档权限（T0–T4）、风控智能体、收款人复述、多因子强验证、人工审核、一次性授权、哈希链审计、熔断、注入防御、数字一致性守卫与受限沙箱。123 个单元测试、离线冒烟与浏览器回归均通过。

它适合比赛演示与产品验证，不能直接承载真实资金。上线前必须完成第 5 节的五项 P0：分布式状态、银行核心联调、真实核验通道、公网反滥用、审计外部锚定。

## 1. 范围与方法

### 1.1 评估对象

- `apps/server`：Fastify API、账号认证、Agent 运行时、策略引擎、风控智能体、审计、沙箱、工具注册表、银行网关。
- `apps/web`：产品 PWA、`/console` 评委控制台、SSE 对话与富卡片。
- `packages/shared`：五档权限常量、风控信号定义、业务模板、类型契约。
- 部署形态：本地单实例；默认合成数据，可选签名 HTTP 银行核心与真实短信 / 人脸 Provider。

### 1.2 本次范围

权限分级、确认与授权、强验证、人工审核、限额与幂等、幻觉防护、提示词注入、审计链、熔断与接管、账号与会话、沙箱、银行接入、PWA 与隐私处理。

不在本次范围：行方准入与联调、支付清算、征信、KYC、活体供应商选型、生产基础设施与监管认证。

### 1.3 方法

代码审查、单元与集成测试、离线冒烟、HTTP 接入冒烟、真实浏览器回归、控制台攻击实验室、公网 HTTPS 实测。未进行渗透测试、压力测试、多实例一致性测试与第三方安全评估。

## 2. 资产、角色与信任边界

### 2.1 资产

- 用户资金、账户余额、交易流水、卡片额度、理财持仓、订阅代扣。
- 操作授权：确认摘要、一次性 grant、强验证挑战、人工审核单。
- 审计日志与决策链路。
- 个人数据：姓名、手机号、卡号、联系人、地址。
- LLM API Key、银行网关密钥、认证签名密钥与系统配置。

### 2.2 角色

- 普通用户：多用户注册或访客体验，数据按 `userId` 隔离。
- 恶意输入者：通过对话注入、伪造身份、诱导模型越权。
- 本地攻击者：可访问演示机文件系统或浏览器。
- 审核席位：演示环境由已登录用户触发审核批准或驳回。
- 外部依赖：LLM 服务、银行核心、短信与人脸 Provider、网络与隧道。

### 2.3 信任边界

| 边界 | 控制 | 现状 |
| --- | --- | --- |
| 浏览器 ↔ API | HTTPS、HMAC 签名 HttpOnly Cookie、SameSite=Lax | 已实现；公网需 `COOKIE_SECURE=1` |
| API ↔ LLM | 只发送意图解析所需文本；手机号、卡号脱敏；模型输出不直接执行 | 已实现 |
| API ↔ 银行核心 | HMAC-SHA256 签名、5 分钟时间窗、nonce、幂等键、Zod 快照校验 | 契约与桩已实现；mTLS 未实现 |
| API ↔ 短信 / 人脸 | HTTP 模式只认 Provider 服务端结果 | 已实现；默认演示通道 |
| API ↔ 磁盘 | 追加式审计、运行时目录隔离、密钥文件 0600 | 文件未加密；无 WORM |
| 控制台 ↔ API | 与产品端共用登录态 | 无独立角色与 RBAC |

### 2.4 主要威胁与控制

| 威胁 | 控制 | 残余风险 |
| --- | --- | --- |
| 模型编造余额、流水或回执 | 事实来自工具结果；数字一致性守卫 | 文案可能生硬；数字已被约束 |
| 提示词注入绕过权限 | 9 类输入规则 + 模型嫌疑 + 服务端策略 / 工具 / grant 独立 | 新话术可能漏报；服务端仍兜底 |
| 确认后改单（TOCTOU） | 摘要绑定参数，执行前重算 | 进程被完全控制时无法防御 |
| 授权重放 | 单次消费、90 秒 TTL、风险等级复核 | 多实例需共享存储 |
| 并发双花额度 | 预留-提交台账 + 用户级串行锁 | 多实例需数据库行锁 |
| 同名联系人转错人 | 歧义澄清 + 联系人尾号 / 银行展示 | 用户误选仍可能发生 |
| 冒充行长或管理员 | 身份声明不构成授权；策略在服务端 | 真实系统需正式角色体系 |
| 删除或篡改审计 | append-only + 哈希链 + checkpoint + 副本演练 | 整文件删除无法阻止，只能发现 |
| 沙箱逃逸 | worker + vm、无 IO、双重超时、静态检查 | vm 不是生产安全边界 |
| PII 泄露给 LLM | 手机号 / 卡号脱敏；联系人只传必要字段 | 证件号、地址等自由文本仍可能进入 |
| LLM 不可用或限流 | 规则引擎、缓存兜底、离线开关、日预算 | 规则覆盖有限 |
| 连续失败或注入轰炸 | 3 次失败或 2 次注入锁定 10 分钟 | 用户级锁定；生产需全局风控 |
| 撞库与暴力登录 | scrypt、IP / 手机号限流、可开关登录 MFA | 无泄露密码库检查 |
| 跨用户越权（IDOR） | 会话、确认、回放、审核均校验 `userId` | 单进程内存态；无集中鉴权服务 |
| CSRF | HttpOnly + SameSite=Lax | 未强制 Origin 校验或 CSRF token |
| 伪造银行核心响应 | HMAC、时间窗、nonce、Zod 校验、失败关闭 | 依赖生产密钥管理与网关 |
| 重复提交双花 | 幂等键 + 写操作 `Idempotency-Key` | 银行侧仍需幂等去重与对账 |
| 绕过人脸或短信 | HTTP 模式只认 Provider 结果；固定码已移除 | 供应商 SDK、活体等级与模板报备待联调 |
| PWA 缓存泄露 | Service Worker 不缓存 `/api/` | 共享设备浏览器缓存仍有风险 |
| 人工审核被滥用 | 审核动作写审计；队列按用户隔离 | 无审核角色、双人复核与操作员强认证 |

## 3. 权限分级说明

### 3.1 五档矩阵

| 档位 | 控制项 | 典型触发 | 服务端决策 | 认证与时限 |
| --- | --- | --- | --- | --- |
| T0 自动执行 | `AUTO` | 余额、流水、账单、持仓、产品对比、异常检测、沙箱统计 | `ALLOW` | 登录态 |
| T1 摘要确认 | `SUMMARY_CONFIRM` | 单笔 ≤ 1000 元的转账、定时转账、AA 收款、冻结卡、取消订阅、锁预算、虚拟卡申请 | `CONFIRM` | 一次性 grant，90 秒 |
| T2 收款人复述 | `SUMMARY_CONFIRM` + `PAYEE_ECHO` | 单笔 1000–5000 元，或风控评分 35–59 | `CONFIRM` | grant + 手输收款人姓名 |
| T3 多因子 | `SUMMARY_CONFIRM` + `PAYEE_ECHO` + `STEPUP_MFA` | 单笔 5000–5 万元，或评分 60–84，或操作类型本身为红色 | `STEPUP` | 人脸；单笔 > 5000 元、挂失、解挂追加短信；挑战 90 秒、3 次 |
| T4 人工审核 | `MANUAL_REVIEW` | 单笔 > 5 万元、评分 ≥ 85、命中风险名单 | 转账 `REVIEW`；其他 `STEPUP` | 延迟到账，10 分钟内可撤销 |
| DENY | — | 单笔 > 20 万元、当日累计 > 50 万元、熔断锁定、策略拒绝 | `DENY` | 提示柜面或提额 |

> 1000 元是 T1 / T2 的分界，也是转账“黄色 / 红色”的分界，不是金额上限。超过 5 万元进入人工审核，不再一刀切禁止。
>
> T4 转账的当前实现以人工复核替代入队前的强验证：受理后直接进入审核队列，不扣款；审核批准即执行。界面文案中的“按 T3 通道执行”与实现存在差异，已列入第 5 节 P1 风险。

### 3.2 静态档判定

档位先由操作类型与金额确定，再交给风控智能体升档。

| 操作类型 | 静态档 |
| --- | --- |
| 只读查询、分析、对比、沙箱统计 | T0 |
| 转账、定时转账、AA 收款、锁预算、礼品 | 按金额档；礼品 > 300 元最低 T3 |
| 理财申购 / 赎回 | 最低 T3 |
| 挂失 / 解挂 | 最低 T3 |
| 调额 ≤ 2000 元 | 按金额档；> 2000 元最低 T3 |
| 冻结卡、取消订阅、虚拟卡申请 | T1（金额档更高时取高） |

转账另看当日累计：本次执行后累计超过 1000 元时，静态风险标为红色，档位至少升到 T3。

### 3.3 金额档与绝对上限

| 单笔金额 | 档位 | 说明 |
| --- | --- | --- |
| ≤ ¥1,000 | T1 | 摘要确认 |
| ¥1,000–5,000 | T2 | 手输收款人姓名 |
| ¥5,000–50,000 | T3 | 人脸；超过 5000 元加短信 |
| > ¥50,000 | T4 | 转账进入人工审核 |
| > ¥200,000 | DENY | 单笔产品上限 |
| 当日累计 > ¥500,000 | DENY | 当日产品上限 |

### 3.4 风控智能体

`policy/riskAgent.ts` 只读服务端账本与会话事实，模型不参与打分。只读节点直接返回 0 分、T0，避免历史流水误升档。

| 信号 | 触发条件 | 权重 |
| --- | --- | --- |
| 金额占比 `AMOUNT_RATIO` | 占可用资金 > 80% / > 50% / > 30% | 28 / 18 / 8 |
| 行为基线 `BEHAVIOR_BASELINE` | 达到近 30 天日均支出 5 倍 / 3 倍 / 2 倍 | 30 / 20 / 10 |
| 首次收款人 `NEW_PAYEE` | 从未转过 / 近 90 天无往来 | 15 / 8 |
| 深夜交易 `NIGHT_HOURS` | 00–05 点且金额 > 1000 元 | 12 |
| 短时频次 `VELOCITY` | 10 分钟内已有 3 笔 / 2 笔转出 | 15 / 8 |
| 拆分规避 `STRUCTURING` | 24 小时内 3 笔 / 2 笔贴近限额阈值 | 25 / 12 |
| 会话风险 `SESSION_RISK` | 已有失败或注入命中 | 10 + min(15, 次数 × 5) |
| 注入嫌疑 `INJECTION_SUSPICION` | 本轮嫌疑度 ≥ 0.5 | 20 |
| 置信度偏低 `LOW_CONFIDENCE` | < 0.6 且金额 > 1000 元 | 12 |
| 风险名单 `BLOCKLIST_PAYEE` | 收款人命中名单 | 100 |
| 诈骗话术 `FRAUD_KEYWORD` | 备注含“安全账户”“配合调查”等 | 25 |
| 收款人改动 `PAYEE_JUST_CHANGED` | 本次会话中收款人被替换 | 15 |
| 新设备 `NEW_DEVICE` | 新设备或新浏览器会话 | 12（预留，未接线） |
| 接近日限额 `DAILY_CEILING_NEAR` | 本次后超过日上限 80% | 15 |

评分区间与建议档位：

| 分数 | 等级 | 建议档位 |
| --- | --- | --- |
| 0–34 | 低 | T1 |
| 35–59 | 中 | T2 |
| 60–84 | 高 | T3 |
| 85–100 | 严重 | T4 |

命中风险名单时 `requiresReview=true`。名单默认只有一条演示数据，可通过配置覆盖。

### 3.5 档位融合

```text
staticTier    = toolTier(node, amount)
agentTier     = max(tierFromRiskScore(score), tierFromAmount(amount))
tier          = max(staticTier, agentTier)
effectiveRisk = max(node.baseRisk, riskFromTier(tier))
tier          = max(tier, tierFromRisk(effectiveRisk))
```

风控只能升档。红色基础操作即使金额很小也至少是 T3；T2 在风险色上映射为黄色，避免与多因子档混淆。

决策映射：T0 → `ALLOW`；T1 / T2 → `CONFIRM`；T3 → `STEPUP`；T4 转账 → `REVIEW`；T4 非转账 → `STEPUP`。

### 3.6 控制项实现

**摘要确认与一次性授权**

- 摘要绑定 `userId | sessionId | runId | nodeId | tool | 规范化参数`，执行前重算。
- 用户确认后签发 `PolicyGrant`，90 秒有效，只能消费一次。
- 执行前校验节点、摘要、TTL、是否已用、当前风险是否高于授权风险。改金额返回 `DIGEST_MISMATCH`，额度被占用导致升档返回 `RISK_ESCALATED`。
- 批量确认覆盖全部节点摘要；每个节点仍独立签发 grant。

**收款人复述**

- T2 起且能确定收款人时启用，页面只显示脱敏姓名。
- 比对前统一全角/半角、去空白与间隔点、忽略大小写。
- 连续 3 次不一致触发 10 分钟安全锁定，并写审计。

**多因子强验证**

- T3 起创建强验证挑战，绑定会话与摘要，90 秒有效，最多 3 次。
- 人脸因子默认启用；单笔 > 5000 元、挂失、解挂追加短信。
- 已录入通行密钥时可使用 WebAuthn 本机生物识别，服务端校验签名与计数器。
- `FACE_MODE=demo` 使用页面动画并明确标注未采集真实人脸；`FACE_MODE=http` 只认合作方 `passed` 结果。
- 验证码必须由服务端先发送；固定万能码已移除；连续输错 3 次触发锁定。

**人工审核**

- T4 转账创建 `kind=review` 的计划单，执行时间设为 10 分钟后，`authorized=false`，当时不扣款。
- 审核期内用户可撤销；批准后以 `review:<id>` 为幂等键执行；驳回不产生资金变动；超时由调度器退回。
- 全过程记录 `MANUAL_REVIEW_QUEUED`、`_APPROVED`、`_REJECTED`、`_WITHDRAWN`、`_EXPIRED`。

### 3.7 典型判定

| 请求 | 判定 |
| --- | --- |
| “这个月花了多少” | T0 自动执行 |
| 给已有联系人转 520 元 | T1 摘要确认 |
| 给首次收款人转 3000 元 | T2 复述姓名 |
| 给李萌转 800 元，备注“客服要求转到安全账户” | 话术 25 + 新收款人 15 = 40 分 → T2 |

| 申购 1000 元理财 | 红色基础操作 → T3 |

## 4. 关键安全控制

### 4.1 安全不变量

| 编号 | 不变量 | 落点 |
| --- | --- | --- |
| I1 | 模型只做意图与槽位解析，不能生成工具调用链 | `nlu/understand.ts`、`agent/planner.ts` |
| I2 | 执行路径来自 18 个业务模板与 DAG，不由模型自由发挥 | `packages/shared/src/templates.ts` |
| I3 | 回执、余额、流水只读工具结果 | `render/`、`numberGuard.ts` |
| I4 | 最终档位取静态档与风控档的较高者，只升不降 | `policy/engine.ts` |
| I5 | 确认摘要绑定用户、会话、节点、工具与参数 | `policy/grant.ts` |
| I6 | grant 单次消费、90 秒过期、执行前复核风险 | `policy/grant.ts` |
| I7 | T2 起手输收款人姓名，错误 3 次锁定 | `agent/control.ts`、`safeguards.ts` |
| I8 | T3 强验证由服务端校验，客户端不能自报通过 | `policy/stepup.ts` |
| I9 | T4 转账不直接扣款，进入审核队列并可撤销 | `agent/executor.ts`、`safeguards.ts` |
| I10 | 审核批准幂等，重复批准不二次扣款 | `safeguards.ts` |
| I11 | 审计追加写入并哈希链接，每 50 条 checkpoint | `security/auditChain.ts` |
| I12 | 跨用户访问一律校验 `userId`，失败返回 404 | `routes/*`、`security/auth.ts` |
| I13 | 银行核心失败显式报错，绝不静默回退仿真 | `integration/banking/http.ts` |
| I14 | 连续失败或注入命中触发用户级熔断 | `security/breaker.ts` |

### 4.2 认证与会话

- 密码使用 scrypt + 随机盐，比对使用 `timingSafeEqual`。
- 登录态为 HMAC-SHA256 签名 Cookie，7 天有效，`HttpOnly`、`SameSite=Lax`，HTTPS 下加 `Secure`。
- 登录、注册、游客、验证码、登录 MFA 均按 IP / 手机号限流。
- 支持登录二次验证、找回密码、修改密码、查看与撤销其他设备会话。
- 每个请求解析 `authUser`，会话、确认、回放、审核均校验归属。
- 审计上下文自动注入 `userId`，审计条目按用户过滤。

### 4.3 幻觉与事实一致性

- 模型只输出意图、槽位与置信度；规划器只实例化模板；渲染层只读工具结果。
- 数字守卫扫描回复中的 `¥金额` 与百分比，必须命中工具证据集合，容差 0.011；失败则回退通用文案并计入拦截统计。
- 交易流水号、持仓 ID、订阅 ID 作为证据返回，可追溯。

### 4.4 提示词注入

- 规则库覆盖 9 类：指令覆盖、提示词窃取、审计破坏、身份伪造、跳过验证、强制转账、角色扮演、数据越权、工具标记注入。
- 累计权重 ≥ 45 阻断，≥ 20 告警；模型侧嫌疑 ≥ 0.75 升级阻断。
- 连续 2 次命中锁定 10 分钟。
- 工具白名单、意图白名单、策略引擎、grant 与额度台账独立于提示词。
- 控制台攻击实验室可现场发送攻击并运行服务端自检。

### 4.5 审计链

- 追加式 JSONL，字段为 `seq | prevHash | userId | type | ts | summary | payloadHash`。
- 哈希覆盖序号、前哈希、用户、类型、时间、摘要与 payload 哈希；每 50 条写入 checkpoint。
- 落盘前脱敏手机号、卡号、token、密码等字段；限制 payload 大小。
- 覆盖注册登录、输入、NLU、注入拦截、规划、策略、确认、grant、强验证、工具结果、额度预留、补偿、熔断、接管、审核、回退、导出与重置。
- 支持整链校验、按 run 回放、副本篡改演练；篡改演练只改副本，不触碰运行主链。

### 4.6 熔断、接管与补偿

- 连续 3 次工具失败或 2 次注入命中，用户级锁定 10 分钟；锁定时不调用 LLM，工具调用直接拒绝。
- 支持中断、人工接管、恢复、终止与逆序补偿；所有状态迁移写审计。
- 补偿只处理可逆的成功节点；不可逆节点转人工工单，避免假回退。

### 4.7 额度、幂等与并发

- 预留-提交台账：`used = COMMITTED + HELD`，`remaining = 1000 - used`；预留 120 秒过期。
- 同一用户的额度变更通过串行锁执行，避免并发“读-判-写”双花。
- 幂等键绑定会话、run、节点、工具与参数；成功结果持久化，重放返回原结果。
- 日切使用业务日期字符串，不依赖定时器。

### 4.8 银行核心接入

- 默认 `simulated`；切到 `http` 后账户、流水、卡片、订阅、持仓与全部资金操作走签名网关。
- HMAC-SHA256 覆盖 method、path、timestamp、nonce 与 body hash；5 分钟时间窗；nonce 防重放。
- 写操作携带 `Idempotency-Key`，网络重试复用同一 key。
- 8 秒超时、有限重试、客户端熔断（5 次失败 / 30 秒冷却）；Zod 严格校验快照；失败关闭。
- 仓库不含真实银行密钥；正式接入需客户绑定、准入、mTLS 与联调。

### 4.9 沙箱

- 独立 worker + `node:vm`，无 `require`、`fs`、`net`、`process`。
- vm 内 800ms 软超时，worker 2.2s 硬终止；内存上限 64MB；返回值大小受限。
- 静态拒绝越界调用，运行时错误写审计。
- 定位为演示级受限计算环境，不作为生产安全边界。

### 4.10 数据与隐私

- 多用户独立合成银行数据；密码哈希与令牌不落明文。
- 提示词发送前对手机号、卡号脱敏；联系人只发送姓名、关系、银行与尾号。
- 审计落盘前脱敏；LLM API Key 只在服务端环境变量，不进入前端、工具输出、日志或仓库。
- 运行时数据位于 `data/`，已 gitignore，可一键重置。
- 业务日期使用可注入演示时钟；安全 TTL 使用真实墙钟，避免冻结时钟导致挑战立即过期。

## 5. 已知风险清单（20 条）

### P0 · 上线前必须处理

1. **单实例状态与存储。** 用户状态、会话、grant、强验证挑战与额度台账保存在 JSON 文件和进程内存，仅支持单实例。重启会丢失进行中的会话与挑战；多实例会破坏额度、会话与审计一致性。生产需 Postgres / Redis、分布式锁与事务边界。
2. **银行核心未完成行方联调。** 已交付签名 HTTP 契约、联调桩与 OpenAPI，缺真实客户绑定、授权同意、mTLS 终止、异步对账回调与历史流水分页。`appSecret` 与 `bref → custId` 映射需由生产环境提供。
3. **核验通道默认演示。** `FACE_MODE=demo` 且未录入通行密钥时，页面动画即可完成人脸因子，界面已标注“未采集真实人脸”；`SMS_MODE=demo` 使用服务端下发的一次性演示码。真实路径已实现，但缺供应商准入、短信模板报备与活体等级约定。
4. **公网反滥用不足。** 认证接口有 IP / 手机号限流，LLM 有全局日预算（默认 500 次）；缺聊天频控、验证码、WAF、账号级滥用检测与成本告警。公网演示存在被刷接口与消耗模型额度的风险。
5. **审计链缺少外部锚定。** 哈希链能发现内容篡改与断链，但本地攻击者可删除或整体替换文件。无 WORM、无 KMS 签名、无可信时间戳与集中日志。生产需 SIEM / 对象锁 / 外部锚定。

### P1 · 生产化阶段处理

6. **人工审核缺少职责分离与入队前验证。** 审核批准接口对已登录用户开放，没有独立审核角色、双人复核与操作员强认证；T4 转账入队前不签发摘要确认、不复述收款人、不做多因子，批准后直接执行。生产需角色权限、四眼原则、入队前强验证与操作留痕。
7. **审核通过未回写额度台账。** `approveManualReview` 直接调用银行转账，未重新预留或提交当日额度，后续交易可能低估当日累计。生产需在批准时重新评估限额并占用台账。
8. **账号体系为原型级。** 已有注册、找回密码、可开关登录 MFA、会话查看与撤销；缺 KYC 与证件核验、设备指纹、账号注销、泄露密码库检查；密码最低 6 位。Cookie 被复制后在有效期内仍可使用。
9. **敏感数据未加密。** `store.json` 保留登录手机号等字段，数据文件未做字段级加密或磁盘加密；密钥文件权限为 0600，依赖主机安全。生产需字段加密、密钥托管与访问审计。
10. **CSRF 依赖 SameSite=Lax。** 未强制 Origin 校验或双提交 token。生产需在网关或应用层补充 CSRF 防护。
11. **控制台无角色权限。** `/console` 对任何已登录用户开放，入口隐藏在「我的」。不暴露他人数据，但会暴露技术链路、审计与攻击实验室。生产需评委访问码、RBAC 或独立部署。
12. **风控数据源有限。** `risk-agent-v1` 已覆盖金额、行为基线、收款人、时段、频次、拆分、会话、注入、置信度、名单、话术、收款人改动与额度余量；`NEW_DEVICE` 信号已定义但未接线；名单为演示数据；缺设备指纹、商户与地区风险、真实反欺诈名单。模型不参与打分，规则权重需用真实样本校准。
13. **沙箱强度有限。** worker + vm 能阻断文件与网络访问，无法覆盖全部逃逸与资源耗尽场景。生产需容器或 microVM、seccomp、cgroup 与网络隔离。
14. **PII 识别不完整。** 提示词与审计对手机号和卡号脱敏；自由文本中的证件号、地址、账号备注仍可能进入模型或日志。生产需输入输出双向 PII 过滤与分级脱敏。
15. **依赖外部大模型。** 业务语句发送给 DeepSeek，极端表达可能误判意图；已有澄清、置信度、规则与离线兜底，无法保证 100%。生产需私有化或专有云模型、评测集、灰度与内容安全。
16. **对账窗口未闭合。** 存在“银行核心成功、客户端确认失败”的窗口；桩实现支持幂等查询与快照，真实网关仍需按接入文档完成对账与结果补偿。
17. **撤销能力受清算时点约束。** 转账冲正、订单取消按可逆语义补偿；真实支付通道的撤销窗口由清算规则决定，不能假设全部可回退。

### P2 · 演示与交付相关

18. **演示时钟与真实时钟分离。** 业务日期默认固定为 2026-10-30 10:00，便于演示计划任务与生日场景；生产需统一可信时间源。
19. **在线 Demo 依赖本机后端与临时隧道。** 页面与静态资源由 Qoder Site 托管，`/api` 由同源 Edge Function 固定转发到本机产品服务（Cloudflare Quick Tunnel）。电脑休眠、隧道重启或后端停机时，Demo 会返回“演示后端暂时不可达”；正式提交需将后端部署到固定公网地址并更新 `APP_ORIGIN`。代理只放行 `/api/*`，不接受请求方指定目标地址，转发 Cookie 与 SSE，不缓存响应。站点已设为公开，任何人可打开并创建独立演示账户；如需收回，可在 Qoder Site 设置中改回私有。
20. **争议处理只到受理，且未做渗透测试。** 工单生成、状态回显与 180 天窗口校验在服务端完成，调查与赔付由银行侧承担。本报告为开发期自查，未做渗透测试、压力测试、多实例一致性测试与第三方安全评估。

## 7. 生产化建议

1. 接入正式 IAM：KYC、设备指纹、登录 MFA 默认开启、操作签名、账号注销；确认与强验证令牌绑定可信设备。
2. 公网入口增加网关限流、WAF、验证码、聊天频控、LLM 预算告警与异常登录监控。
3. 使用 Postgres / Redis 承载账号、额度台账、幂等、会话与分布式锁；敏感字段加密；审计接 WORM / SIEM。
4. 人工审核补齐审核角色、四眼原则、操作员强认证；入队前完成确认与强验证，批准时重新校验限额并占用台账。
5. 私有化或专有云部署模型，建立意图、槽位、注入与话术评测集，加入灰度与回归门禁。
6. 沙箱迁移到容器或 microVM，限制 CPU、内存、网络与系统调用。
7. 风控接入设备、地理位置、商户、真实名单与人工复核数据，校准权重并建立误报/漏报监控。
8. 建立安全开发生命周期：威胁建模、代码审计、依赖扫描、渗透测试、应急演练与合规评估。

## 9. 结论

原型已形成“模型理解 → 模板规划 → 服务端策略 → 确认 / 复述 / 强验证 / 人工审核 → 工具执行 → 审计”的闭环。五档权限与风控智能体把大额交易从一刀切阻断改为分级放行；确认摘要、一次性授权、幂等与台账覆盖了改单、重放、并发与重复提交；审计链、熔断与接管提供了可追溯与可止损能力。

当前边界同样明确：单实例存储、未联调银行核心、默认演示核验、公网反滥用不足、审计无外部锚定，以及人工审核缺少职责分离与入队前验证。完成第 5 节 P0 与第 7 节建议后，才具备进入真实资金场景的前提。
