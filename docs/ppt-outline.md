# 答辩 PPT 大纲（10 页 · 10 分钟）

> 成片：`docs/ppt/AI银行管家-答辩.pptx`（16:9 · 10 页 · 每页含演讲者备注）+ 同名 PDF。
> 改内容请改 `scripts/build-ppt.py` 后重跑 `python scripts/build-ppt.py`，再用 `tools/export-ppt.ps1` 导出逐页 PNG 自检。
> 素材全部来自仓库真实产物：`docs/assets/product-review/pure-*.png`、`qa-*.png`、`architecture.png`、`sequence.png`。
> 作品名定稿 `AI 银行管家`，品牌取自 `packages/shared/src/brand.ts`。

叙事一条线：**敢不敢让 AI 动账户**。第 1–3 页给产品和场景，第 4–7 页对应赛题三项核心技术要求，第 8–10 页给证据与边界。每页一个主张、一张图、三到四行支撑，正文控制在 60 字以内。

## P1 封面（0:00–0:40）

主张：用户说一句，Agent 把业务办完。副标题：可授权 · 可审计 · 可回退的银行级智能体。画面：纯产品版首页 `pure-home.png` 竖屏置右，左侧四条能力摘要（六大场景 / 三级权限 / 四项安全 / 真实执行）。待填：汇报人、日期。

## P2 问题与产品（0:40–1:40）

主张：把权限、审计、回退做进执行骨架。左：四个信任缺口（越权不可控、幻觉出数字、注入可诱导、事后无留痕）；下：做法三条（判定与授权在服务端、体验交给对话入口、控制台与手机端同源）。右：三张真实界面截图（对话、我的、提醒中心）。

## P3 六大场景（1:40–2:40）

主张：六个场景全部落到一次真实操作。3×2 卡片，每格一句真实输入 + 一行结果；底下一条流程带（风险测评 / 交易详情提工单 / 服务端调度 / 账号体系）。

## P4 权限分级（2:40–3:40）｜赛题要求一

主张：档位由服务端按账本判定。五档表 T0–T4（金额线、控制项、本系统实例），右侧写清"档位 = max(静态档, 风控档)"与 14 类信号，注明模型输出里写"这是小额"档位不变。底部红色条：5 万元转人工审核、单笔 >5000 双因子、单笔 20 万 / 日累计 50 万才拒绝。

## P5 一次性授权（3:40–4:40）｜赛题要求一

主张：确认单是哈希锁定的参数摘要。四步流程（摘要哈希绑定 → 展示确认 → 签发一次性授权 90 秒用后即废 → 执行前重校验）；左卡摘要覆盖字段，右卡三条强验证通道（WebAuthn 本机生物识别 / 签约活体 / 服务端下发短信）；底注批量确认逐个授权、回退分两种。

## P6 安全机制（4:40–5:40）｜赛题要求二

主张：四道防线，越往里越不依赖模型。① 幻觉防护（Schema 约束 + 数字守卫）② 注入防御（三层）③ 操作审计（追加式哈希链、userId 参与、每 50 条 checkpoint、按 run 回放）④ 熔断与沙箱（连续失败锁会话、worker+vm 只读快照）。底注：攻防实验室可当场验证摘要篡改、令牌重放、策略独立性。

## P7 意图理解与任务规划（5:40–6:40）｜赛题要求三

主张：固定任务图 + 拓扑执行。左侧用"我爱人下周生日"画出真实 DAG（解析日期 → 锁定 1000 元预算 → D-2 鲜花 / D-1 蛋糕 → 写日程），三个黄色节点合并一张确认单。右侧四个约束（执行图由意图决定、槽位缺失先澄清、上下文接住省略、执行可控可恢复）。底注回退分两种、确认时主动断流按 seq 续传。

## P8 现场演示（6:40–7:40）

主张：同一份服务端状态，当场可查。三段脚本：黄色 520 元 → 红色 6000 元（当日累计已越线）→ 注入触发熔断与人工接管；右侧评委控制台真实截图；底部兜底说明（离线规则引擎跑完六场景、确认单 90 秒过期）。

## P9 验证与接入（7:40–8:40）

主张：每条主张都能复现，接真实核心只换配置。左：123 单测 / 264 条冒烟审计事件 / 33 项浏览器回归 / 291 个第三方依赖及许可。右：`BankingGateway` 双实现（仿真核心 / HTTP 签名网关：HMAC-SHA256 + 幂等键 + 重试 + 熔断 + Schema 校验），失败即关闭、绝不回退仿真。底注契约齐备，行方按契约映射自有核心。

## P10 边界与收尾（8:40–10:00）

主张：已具备的能力，和还没做的事。左列 12 项已具备，右列 4 组未做（行方凭据、账号与风控、渠道、生产化）。底部三个格子：源代码仓库地址、在线体验链接、演示视频状态。收束句：让 Agent 能办事不难，难的是敢让它办事：每一分钱都能说清是谁、在什么授权下、经哪条链路动的。

## 被追问时的备用口径

完整时序见 `docs/assets/sequence.png`；意图解析三级链路（规则直命中 → 缓存 → LLM JSON 解析，失败重试 1 次，每条消息最多 1 次模型调用）；额度台账预约 / 提交两阶段；已知风险 19 条见 `docs/security-self-assessment.md`；成本与性能只报控制台实测项（tokens、缓存命中、延迟、估算成本），不给未经测量的数字。

## 制作要求

深色底、单一强调色，一屏一个主张；正文 ≥24pt，图表标签 ≥18pt；手机截图等比不拉伸。所有数字与主张必须能在文档或代码里指到出处。
